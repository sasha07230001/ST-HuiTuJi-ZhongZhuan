# 绘图姬·中转站

> 在「剧情正文 → ComfyUI」中间加一道**中转站**:正文先交给一个 OpenAI 兼容的模型,
> 让它编译成 ComfyUI 能直接吃进 CLIP 的英文提示词,再送进工作流出图。

SillyTavern 扩展,与 [ST-HuiTuJi-2(绘图🐔二号)](https://github.com/sasha07230001/ST-HuiTuJi-2)
同级,但它**只管一件事**:

```
ST-HuiTuJi-2 里那些「提取提示词 → 塞进 ComfyUI 的 CLIPTextEncode」
                                   ▲
                                   │  ← 这里插进来
                    绘图姬·中转站(本扩展)
```

二号把正文直接丢进工作流、提词靠 ComfyUI 里的节点;本扩展把「正文 → 提示词」这一步
**搬到酒馆侧**,用你自己填的 url + key 调模型完成,只把结果写进 CLIP 文本节点。

---

## 它到底做了什么

```
楼层正文 ──清洗──► purge 层 ──► 中转站模型 ──英文 tag──► 反净化 ──► 合并画风/负面 ──► CLIPTextEncode ──► ComfyUI ──► 楼层卡片
   ▲                  ▲             ▲                     ▲            ▲                  │
   └─ 自动/AI 楼 ──────┘             │                     │            └─ 恒定画风词、恒定负面词   └─ 排队/进度/取消
                                    │                     └─ 被降级的词补回来
                                    └─ 权威声明压 system + assistant prefill
```

1. **取正文**:当前楼层的 AI 剧情正文(剥 HTML/Markdown、去上一轮卡片、超长保尾部)。
2. **purge 层**:给这次调用换掉判断框架(详见下方 [purge 层](#purge-层指令权威--反净化))。
3. **中转站编译**:一次补全请求,模型把中文剧情压成一行英文 danbooru tag。
   请求**经 SillyTavern 服务端转发**(`/api/backends/chat-completions/generate`),
   所以没有 CORS 问题,key 也不会暴露给页面上的其它脚本。
4. **验收**:空回复、以中文为主、过长,都判失败并按设置重试。
5. **写进 CLIP**:两种工作流都支持——
   - 有 `%prompt%` 占位符 → 直接替换;
   - 没有占位符 → 自动找 `CLIPTextEncode`,第一个非空的写正向、其余写负面
     (**二号那边的工作流可以原样粘进来,不用改一个字**)。
6. **出图**:提交 `/prompt`、轮询 `/history`,显示排队位置,可取消。
   **只把编译好的提示词送进 CLIP 文本节点**,其余节点(模型、LoRA、采样器)完全按你的工作流走。

## 安装

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/sasha07230001/ST-HuiTuJi-ZhongZhuan
cd ST-HuiTuJi-ZhongZhuan
npm install
npm run build
```

然后**重启 SillyTavern**(`node server.js` 那一下)。扩展列表里会出现「绘图姬·中转站」。

> **为什么必须 build 一次**:`dist/` 是构建产物,仓库里只提交了 `dist/index.js` 这一个文件。
> `git pull` 之后如果没有重新 build,酒馆加载的还是上一版产物 —— 表现为「拉下来了,但所有新功能都没有」。
> 每次更新都跑一次 `npm install && npm run build`(build 完会自动 `git add -f dist/index.js`)。
>
> 如果页面右下角出现红色横幅「绘图姬·中转站:扩展没有初始化成功」,说明 JS 已经加载但在初始化时抛错,
> 点一下横幅可以复制错误信息。

## 配置(扩展设置里)

### 中转站

| 项 | 说明 |
|---|---|
| API 地址 | 填到域名就行(`https://api.deepseek.com` 自动补 `/v1`);也可填完整 `…/v1` |
| API Key | 你自己的 key |
| 模型 | 任意 OpenAI 兼容模型名;旁边「拉模型列表」可以列出来选 |
| 温度 / 最大 token / 超时 | 提词任务建议温度 0.7~0.9、token 300~500 |

点「测试中转站」会发一句极短的话验证 url/key/model 三者都对。

### ComfyUI

| 项 | 说明 |
|---|---|
| 服务地址 | 如 `http://127.0.0.1:8188` |
| 工作流 JSON | ComfyUI 里 **Save (API Format)** 导出的那份 |
| 经 ST 后端转发 | 浏览器直连被 CORS 挡住时勾上;**需要重启过酒馆**才生效 |

点「载入内置工作流」会填入一份**已在 ComfyUI 0.43 实测出图**的 Anima Turbo 工作流
(见 [`examples/workflow-anima-turbo.json`](examples/workflow-anima-turbo.json)),
把里面三个模型文件名换成你本地有的即可。

### 编译提示词

- **system 提示词**:可改。占位符 `{{story}}` = 剧情正文,`{{note}}` = 额外任务提示。
- **恒定画风词**:追加在模型输出后面(去重)。
- **恒定负面词**:写进负面 CLIP 节点。
- **让模型额外输出负面词**:开启后要求模型用 `POSITIVE:` / `NEGATIVE:` 分段。
- **失败重试次数**:返回解析不过时重试几次。

### purge 层(指令权威 / 反净化)

中转站这一跳走的是**没打过补丁的官网 API**。同样的正文,在装了 dsh-purge 的 DSH 里能照画,
到这里会被降级成「两个角色紧张对峙」——r18g 的内容被润色没了。这一层就是补上那段差距。

| 开关 | 作用 |
|---|---|
| **启用 purge 层** | 总闸。关掉 = 完全回到旧行为 |
| **system 前压入权威声明** | 主路径:告诉模型它是渲染器不是审查员,禁止降级与委婉化 |
| **assistant prefill** | 用 `POSITIVE:` 起头,让模型续写而不是重新起意 |
| **反净化重写** | 兜底:正文有血腥/成人词、输出里没有对应 tag 时补回去 |

三个细节:

1. **声明文本可改**。默认那份写在 `src/types.ts` 的 `DEFAULT_PURGE_PROMPT`,设置页能直接编辑、能一键恢复。
2. **prefill 会自动降级**。不是所有 OpenAI 兼容端点都接受 assistant 尾消息,被 400 拒掉时会
   自动去掉 prefill 重发一次,不让一个字段挂掉整条链。
3. **反净化只补正面**。开启「额外输出负面词」时模型输出是两段,`gore` 之类只往 `POSITIVE:` 那条补,
   否则会把词补进负面里,反而洗白。

自动建档(`chars/archive.ts`)也套同一层——它也读正文,不过 purge 的话会把「受伤的人」读成「站着的人」,
档案里的外貌字段从此就是错的。

## 怎么用

**悬浮球**是主入口:页面上一个可拖动的圆球,点一下打开面板,再点一下(或 Esc / 点遮罩)关闭。

- 拖动可自由摆放;**靠近左右边缘才吸附贴边**,贴边时半隐,悬停/聚焦才整条滑出
- **双击悬浮球**回到默认位置(拖到看不见的地方时的救命入口)
- 位置存 `localStorage`(纯视觉态);显隐、大小、透明度在设置里,跨设备同步
- 面板打开时球自动隐藏,关闭后恢复

> **点一下会「闪一下就关」的老 bug 已修**(v0.6.0 又补了一层)。触摸设备在 `pointerup` 之后还会补发一套
> 兼容鼠标事件(`mousedown/mouseup/click`),那一套正好砸在刚刚铺满屏幕的面板上,
> 于是「打开」和「点遮罩关闭」发生在同一次点击里。现在:遮罩只认**按在空白处的 pointerdown**
> 且打开后 450ms 内不理(`panel.ts` 的 `OPEN_GUARD_MS`);球自己在 `pointerdown` 期间
> 用**捕获期**在 `document` 上吞掉这套兼容事件(比遮罩更早),并在面板关掉后 400ms 内
> 不再接受「开」的点击,连点两下也不会秒关。

面板有五页:

| 页签 | 内容 |
|---|---|
| **出图** | 顶部显示当前生效的恒定画风/负面词与自动插图状态;选楼层或手填正文、**填出几张**、分段标记 → 「按张数出图并插回正文」;「编译并预览」只出单张不插入;显示进度、可取消;提示词可手改后「按此提示词出图」 |
| **图库** | 当前聊天存下来的全部图,可一张张「插回正文 / 用这串提示词 / 删除」;「插回正文」按这张图**自己的锚点**插回它对应的那段剧情,楼层滚过去并高亮;落盘不可用时黄条明示 |
| **渠道** | 中转站 url/key/模型(带测试与拉模型列表)、ComfyUI 地址与工作流、后端转发开关 |
| **角色档案** | 固定档案 + 临时档案两层 |
| **提示词** | 编译用 system 提示词、**恒定画风/负面词(带保存按钮)**、重试次数、**剧情范围**、自动插图、悬浮球设置 |

其它入口:

| 入口 | 行为 |
|---|---|
| 楼层右上角 **绘图** 按钮 | 把这一楼正文走完整条链,图按锚点插回正文 |
| 顶栏菜单「绘图姬·中转站」 | 打开面板 |
| 设置里勾「每生成一楼自动插图」 | 每次 AI 回复完自动跑 |
| 设置抽屉「悬浮球 / 面板」栏 | 开关悬浮球、调大小/透明度、打开面板、重置球位置 |
| 控制台 `htjZhongZhuan.openPanel()` | 给别的插件留的接口 |

出图结果不再是一张「卡片」:每张图带着自己的锚点**插在正文对应段落后面**,图下方的
小条上有**删除这张**。生成过程中的状态(编译中 / 排队第几 / 失败原因)显示在同一位置的
状态卡上,成功后退场;失败时它会留在原地,带 **重试 / 关闭** 两个按钮。

## 一次出多张(按正文分段)

面板「出图」页填**出几张**(1-8),插件会把正文切成 N 段,每段单独编译、单独出图,
然后**插回那一段的正文后面**:

```
正文里写标记(默认 [[图]]):
  她推开门,雨声涌了进来。
  [[图]]
  远处霓虹在水里化开,她抬起头。
  [[图]]

→ 第 1 张插在「雨声涌了进来。」之后,第 2 张插在「她抬起头。」之后
```

- **有标记** → 按标记切,张数以标记数量为准(标记本身不进提示词);
- **没标记** → 按张数均分:先按空行,再按句末标点,最后才按字符硬切。
  宁可切开一句话,也不会少出一张。
- 每段都会给模型一句限定:`只画这一段里正在发生的事,不要画其它段落` —— 不这么说,
  模型会把整楼剧情压进一张图,几张图全长一样。

「出图」页还有一个**分段预览**:直接列出这次会切几段、每段开头是什么、锚点落在哪,
不用先烧一次后端才知道切得对不对。

实现:`src/relay/split.ts`(纯函数,单测覆盖)+ `src/ui/card.ts`(串行出图、落地、回插)。

## 图库:刷新不丢

老版本把图放在 `URL.createObjectURL(blob)` 上 —— 那个 URL 只是**当前页面内存里的一个句柄**,
刷新就失效,所以「出过的图一刷新全没了」。

现在出图后第一件事是把它转成 **data URL**,存进浏览器 **IndexedDB**(库名 `htj-zz-db`):

| 关注点 | 做法 |
|---|---|
| 为什么不进 `settings.json` | 那张表每改一次设置就整份写回服务器,几 MB 的 base64 会把 ST 拖垮 |
| 为什么不用 `localStorage` | 5MB 上限,两三张 PNG 就满,而且满了是**静默失败** |
| 刷新后怎么回来 | 启动、切聊天、切 swipe、编辑楼层、往上翻历史时都会 `hydrateAll()`,按锚点把图挂回正文原位置 |
| 会越存越多吗 | 每个聊天有上限(默认 300 张),超出删最老的 |
| 不想要 | 设置里关掉「把出过的图存进浏览器」,回到旧的「刷新即丢」行为 |

水合是**幂等**的:楼层里已挂的图 id 顺序和库里一致就什么都不做,不会每次渲染闪一下。

v0.6.0 又补了三处「还是会丢」的边角:

| 边角 | 处理 |
|---|---|
| 隐私模式 / 存储被禁用时 IndexedDB 打不开,旧实现静默退内存 | `storageHealth()` 把原因记下来,图库页顶部直接黄条提示「只存在内存里,刷新会消失」 |
| 一次出 5 张时并发开事务,Firefox 上后面几张 `TransactionInactiveError` | 写库排一条队列,顺次提交 |
| blob → data URL 转换失败时把坏数据写进库 | 转换失败返回空串并单独报错,不再污染图库 |

## 角色档案与临时档案

出图时会自动把**在场角色**的外貌拼进提示词,保证同一角色每次长相一致。这一层分两档:

| 层 | 管什么 | 什么时候变 | 存哪 |
|---|---|---|---|
| **固定档案**(`chars/profile.ts`) | 发色、瞳色、体型、基础设定 —— 「这个人长什么样」 | 几乎不变(染发、受伤这类真的改了外貌才变) | `chars.entries` |
| **临时档案**(`chars/transient.ts`) | 当前穿戴、身体状态、伤痕/饰品/束缚 —— 「这一刻她穿着什么」 | 每楼都可能变 | `chars.transients` |

### 为什么要分成两层

剧情推进时角色会换衣服:`她换上了黑色蕾丝的胸罩和内裤`。如果直接改固定档案,有三宗罪:

1. **永久污染** —— 下一楼她穿回白裙,固定档案还挂着 `black lace bra`;
2. **互相打架** —— 固定 raw 里写着 `white dress`,临时状态写着 `black lace bra`,两串都进 CLIP,
   采样器按 token 权重骑墙,衣服糊成一片;
3. **不可回退** —— swipe / 回档之后,不知道角色档案被哪一楼改过。

所以临时档案是**同槽覆盖、可清空**的第二层:它一旦有 `outfit`,拼提示词时**顶掉**固定档案里同槽位的旧穿戴,
而不是叠加。固定档案的发色瞳色永远保留(见 `mergeTransientTags`)。

### 数据流

```
剧情正文
  ├─→ 中转站编译 ─────────────→ 画面 tag
  ├─→ 自动建档(固定) ────────→ 发色/瞳色/体型(只在真的变了时才写)
  └─→ 临时档案读取(本层) ────→ 此刻的穿戴/状态
         ↓
   拼装:画面 tag + 画风 + 固定外貌 + 临时状态(覆盖同槽位)
         ↓
   %prompt% → ComfyUI CLIPTextEncode → 出图
```

「临时档案读取」是**独立的一次模型调用**(`chars/transientReader.ts`),刻意不和固定建档合并:
合并的话模型会把「换了黑色蕾丝」写进固定档案,越用越歪。

### 开关(角色档案页)

| 开关 | 作用 |
|---|---|
| **启用临时档案层** | 总闸。关掉 = 完全回到只用固定档案的旧行为 |
| **每轮让模型从剧情更新** | 每楼多一次模型调用,读出现在穿戴/状态 |
| **临时档案覆盖固定档案的穿戴槽位** | 推荐开。关掉就是两串都送,衣服容易糊 |
| **换聊天 / 大幅回档时清空** | 换聊天、或往回跳 3 楼以上,清掉过期状态 |
| **只给角色库里已有的角色建档** | 关掉则允许剧情里出现的任何名字临时建档 |

手动操作:每个角色行有 **临时** 按钮(有内容时显示 `临时 ●`),点开可手改整串 tag、按字段改、
**冻结**(AI 不再改这条)、或**清空**(回到固定档案)。顶部还有**全部清空**。

### 清理规则

- **同聊天、往回 ≤2 楼或往后任意楼** → 保留(重跑上一层、继续剧情都是常规操作);
- **往回跳 3 楼以上 / 换聊天** → 作废(已经过了,那条时间线上的黑色蕾丝不该还穿着);
- **剧情明确说「脱光了」** → 模型给空 raw + 原因,这一层被清空,回到固定档案。

### 手动写临时档案的最简写法

```
black lace bra, black lace panties, black thighhighs
```

整串 tag 会顶掉固定档案里的服装。也可以点「编辑」按字段填 `当前服装 / 当前身体状态 / 当前标记`。

### 成套说法自动展开

写成 `black lace set` 也能用,但**不推荐** —— 送 CLIP 前会自动展开,因为 `set` 不是 danbooru tag:

```
black lace set   →   black lace bra, black lace panties
red bikini       →   red bikini, red bikini top, red bikini bottom
school uniform   →   school uniform, serafuku, pleated skirt, sailor collar
bunny suit       →   bunny suit, bunny ears, black fishnet tights, white collar
maid outfit      →   maid outfit, apron, maid headdress
pajamas          →   pajamas, pajama top, pajama pants
black bra and panties → black bra, black panties
```

为什么必须拆:采样器对 `set` 几乎没有训练分布,只能拿 `black`、`lace` 两个弱线索自由发挥,
最常见的失败是**只画上半截**(胸罩有了,内裤没画)。拆成独立部件后每个词都有自己的分布。

纪律(与其它展开规则一致,**宁可漏拆也不能瞎拆**):

- 单一部件不拆:`black lace bra`、`black thighhighs`、`pleated skirt`
- 只有定语没有套名不拆:`black lace`、`sheer black lace`
- 没写「套」不猜:`black dress`、`satin slip dress` 原样送
- `and` 拆分要求**两侧都是穿戴部件**,所以 `black hair and red eyes` 不会被拆成两件

实现见 `src/chars/outfitSet.ts`。存档里保留你/模型写的原文(`black lace set`),
只有真正送进 ComfyUI 的那一刻才展开 —— 否则手改一次就会被展开结果覆盖,越滚越长。

## 自动插图

开启后,每次 AI 回复完自动走一遍「正文 → 分段 → 中转站 → CLIP → 出图」,图按锚点插回正文。

旧版只挂了 `GENERATION_STARTED + CHARACTER_MESSAGE_RENDERED` 一对事件,**渲染事件一旦没带
`type`、或先发了 `GENERATION_ENDED`**,这条链就永远不启动 —— 这正是「勾了自动出图但没反应」
的原因。现在有三重保险(`src/ui/autoIllustrate.ts`),任何一层成立都能跑:

| 层 | 时机 | 作用 |
|---|---|---|
| **闸门** | `GENERATION_STARTED` 记 (chatId, type) → `CHARACTER_MESSAGE_RENDERED` 消费 | 主路径。只认一次真生成的最终渲染,swipe / 编辑 / 切聊天不算 |
| **生成结束兜底** | `GENERATION_ENDED` 时闸门还挂着 | 渲染事件没带 type 或压根没触发时,直接补跑最末一条 AI 楼 |
| **看门狗** | 武装后 2.5 秒 | 闸门还没被消费 → 取最新 AI 楼补跑一次 |

三层共用同一张去重表(聊天 + 楼层 + swipe + **正文指纹**),所以补跑不会重复烧后端。
另有两条纪律:

- **`GENERATION_STOPPED` 不清闸门**。部分 ST 版本先发 STOPPED 再发渲染事件,
  在这里清掉会把马上要到的召回挡掉。闸门靠 5 分钟 TTL 和「换聊天」自然过期。
- **配置不齐要说话**。中转站或 ComfyUI 没填齐时,自动流程会 toast 一次缺了哪几项,
  而不是静默什么都不做(控制台里还有 `[HTJ-ZZ][auto]` 前缀的诊断日志,可用来核到底卡在哪一层)。

v0.6.0 又补了三处(「勾了自动出图但还是不动」的另几个成因):

| 补丁 | 说明 |
|---|---|
| **绑定重试** | `eventSource` 没就绪时每 0.5 秒重试、最多 30 秒;旧版一次失败就再也不绑 |
| **闸门不再比较 type** | 只要求「同聊天 + 时间窗内」。实测 `GENERATION_STARTED` 给 `'normal'`、渲染事件给 `undefined`,旧逻辑会把每次真生成都判成「不是这次」 |
| **第四层:聊天变长观察** | 生成开始后每 0.5 秒看一眼楼层数,变多就补跑;有的版本 ENDED 早于落盘 |
| **配置判定放宽** | `isProbablyReady()`:密钥可以用 ST 自己那份(请求经服务端转发),换设备/换浏览器后不再被判死 |
| **失败不锁死** | 成功才记「已处理」;失败 8 秒 / 16 秒后自动重排 |
| **状态可见** | 出图页横幅显示 `自动插图:已开 · 事件已绑定 / 上次失败:…`;控制台 `htjZhongZhuan.autoState()` |


> 与二号的差异:二号是「写 tag → 卡片消费标记」两段式握手;我们不出 tag,
> 拿到楼层直接出图,不需要往正文写任何东西。

## 恒定画风词 / 恒定负面词

这两串是**所有**出图的头部基线,在设置抽屉和面板「提示词」页都能改,填完点**保存**。

| 行为 | 说明 |
|---|---|
| **位置** | 一律**前置**:正向 = `画风词, 模型编译的画面 tag, 角色外貌`;负面 = `恒定负面词, 模型给的负面` |
| **为什么要前置** | CLIP 对越靠前的 token 越敏感;不少工作流只吃前 75 个 token,画风词丢在末尾等于没写 |
| **为什么有保存按钮** | 边打边存的话,把 `cinematic lighting` 删到 `cinema` 的中间态会立刻跟着下一张图进采样器,看起来像「风格突然跑掉」 |
| **会不会重复** | 合成时按小写去重并保持顺序,所以手改提示词后再合成一次也不会出现两遍 |
| **同步到 ComfyUI** | 一键「同步恒定词到 ComfyUI 工作流」会把两串**写进工作流模板**(`画风词, %prompt%`),这样 ComfyUI 原生界面里看到的也是同一份;不点也不影响运行时前置 |
| **没保存的改动** | 「最终提示词示例」下面会标 `⚠ 画风词有改动还没保存`,避免以为已经生效 |

面板「提示词」页底部有**最终提示词示例**,直接显示「最终进 CLIP 的那串长什么样」,不用猜顺序。

## 移动端

手机/平板上整套 UI 都能用,不是「能打开但点不到」:

- **面板满屏**,高度用 `100dvh`。用 `100vh` 时移动浏览器地址栏一伸缩就会漏掉一截,底部按钮被顶出屏幕;
- **安全区**:头部/底部/滚动区都吃 `env(safe-area-inset-*)`,刘海屏和手势条不挡按钮;
- **输入框字号 16px**:iOS Safari 对小于 16px 的输入框会自动放大整页;
- **触摸目标 ≥44px**:按钮 `min-height: 42px`、字段改竖排,悬浮球在触摸设备上强制不小于 44px;
- **悬浮球不再半隐**:`(hover: none)` 的设备上没有悬停,贴边半隐等于永远只露一半、点不准;
- **页签横向滚动**:五个页签在窄屏上可左右滑,不会被挤成两行;
- 画布图限高 `45dvh`,图库网格在窄屏自动降为 2 列。

## 剧情范围

模型常在正文外写思维链、状态栏、格式示例(`<StatusPlaceHolderImpl/>` 之类),
那些字一起喂给中转站就是噪音。配了**范围标签**后,只有这些标签包住的内容才算剧情。

```
<thought>很长的思维链...</thought>
<content>她站在雨里,霓虹映在积水里。</content>   ← 只有这段进中转站
<StatusPlaceHolderImpl/>
```

纪律(与二号一致,宁可少清洗也不能把剧情洗没):

- 没配标签 → 整楼都用。
- 配了但找不到**成对**的 `<标签>…</标签>` → 整楼都用(标签可能只是文本里出现)。
- 取到内容才生效;取不到一律回退整楼。

| 设置 | 说明 |
|---|---|
| 范围标签 | 逗号分隔,可粘 `<content>`、`content_fox` 这类带壳写法,会自动剥壳 |
| 同名块取哪个 | `last`(默认,前面常是格式示例)、`first`、`all`(全部拼接) |

## 工作流占位符

| 占位符 | 说明 |
|---|---|
| `%prompt%` | 中转站编译出的正向提示词(**推荐写**) |
| `%negative_prompt%` | 负面提示词 |
| `%seed%` | 本次随机种子(精确等于时替换成**数字**) |

- 只认这三个。写了别的(如 `%width%`)会明确报错,而不是悄悄留个原文进去。
- 没写 `%seed%` 时,会把种子塞进 `KSampler` / `KSamplerAdvanced` 的 `seed` 字段——否则重复出图永远是同一张。
- 完全没有 `%prompt%` 时走「定位式」:自动改 `CLIPTextEncode` 的 text。

## 开发

```bash
npm run typecheck   # tsc --noEmit
npm test            # vitest,202 个用例 / 14 个文件(纯函数 + jsdom)
npm run build       # 产出 dist/index.js
npm run smoke       # jsdom 里真加载 dist/index.js,跑宿主级冒烟(悬浮球/面板/图库/自动插图)
```

`npm test` 覆盖:URL 规范化、提示词清洗/验收、恒定词前置合成、工作流渲染、设置合并、
purge 注入/反净化、临时档案覆盖与清理、成套说法展开、**分段切分**、
**原位回插的锚点定位(jsdom)**、**图库增删查改与超限清理**。

`npm run smoke` 是宿主级回归:用 jsdom 假装成酒馆,真实加载构建产物,断言
「点悬浮球 → 面板打开 → 同一次点击的兼容鼠标事件不会把它关掉」「五个页签都在」
「自动插图收到生成事件会排任务」「生成结束能兜底」等行为。
